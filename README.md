# Kamchatka Parser

Консольный инструмент на Python для преобразования PDF-протокола соревнований
в структурированный JSON. Извлекает данные гонки, этапы, участников, результаты
и штрафы, проверяет согласованность времени и сохраняет предупреждения
для последующей проверки.

Работает локально, без подключения к базе данных и API.

Текущая версия проверена на итоговом протоколе «Берингия. Авача — 2026».
Название гонки, год, даты, количество этапов и участников читаются из документа.
Правила распознавания рассчитаны на структуру этого протокола; совместимость
с другими шаблонами PDF и другими годами пока не проверена.

## Возможности

- Чтение всех страниц PDF с текстовым слоем.
- Фильтрация серых символов водяного знака используемого образца.
- Извлечение названия гонки, года, дат и места проведения.
- Извлечение погодных условий, главного судьи и главного секретаря.
- Разбор номеров и расстояний этапов.
- Извлечение стартового номера, ФИО, года рождения, региона и дисциплины участника.
- Разбор времени этапов и общего результата, включая длительности больше 24 часов.
- Обработка обозначений `DNF`, `DNS` и `DSQ`.
- Разбор штрафного времени в минутах или секундах и ссылки на пункт правил.
- Проверка уникальности стартовых номеров и соответствия результатов этапам.
- Проверка суммы времени этапов у финишировавших участников.
- Запись JSON в UTF-8 с сохранением русских букв и предупреждений.

## Требования

- Python 3.10 или новее.
- Библиотека `pdfplumber`.
- Исходный PDF с текстовым слоем в поддерживаемом формате.

Разбор исходного протокола проверен на Python 3.14.7 и `pdfplumber` 0.11.10.
Путь к исходному PDF нужно явно указать при запуске.

## Установка

Команды для Linux и macOS:

```bash
git clone https://github.com/Chevalier3388/Kamchatka_parser.git
cd Kamchatka_parser
python3 -m venv .venv
source .venv/bin/activate
python -m pip install pdfplumber
```

## Использование

Все примеры ниже выполняются из корня репозитория с активированным окружением.

### Сохранение рядом с PDF

```bash
python protocol-parser/parse_protocol.py --pdf /путь/к/protocol.pdf
```

Результат будет записан в `/путь/к/protocol.json`: в ту же папку,
с тем же именем и расширением `.json`.

Если исходный протокол `Total_result_Avacha-2026.pdf` находится в корне репозитория:

```bash
python protocol-parser/parse_protocol.py --pdf Total_result_Avacha-2026.pdf
```

Параметр `--pdf` обязателен. Без него скрипт сообщает, что нужно указать файл,
и завершает работу. Автоматического поиска PDF нет.

### Выбор выходного файла

```bash
python protocol-parser/parse_protocol.py --pdf protocol.pdf --output results/protocol.json
```

Папки для выходного файла создаются автоматически. В `--output` нужно указывать
путь к файлу, а не существующий каталог. Пути могут быть абсолютными или
относительными к текущей рабочей папке. Пути с пробелами нужно заключать в кавычки.

**Существующий выходной файл перезаписывается.**

### Справка

```bash
python protocol-parser/parse_protocol.py --help
```

| Параметр | Назначение |
| --- | --- |
| `--pdf` | Обязательный путь к исходному PDF-файлу. |
| `--output` | Путь к JSON. По умолчанию — рядом с PDF, с тем же именем. |
| `-h`, `--help` | Вывод справки. |

После успешного сохранения скрипт печатает путь к JSON и имеющиеся предупреждения.

## Структура JSON

Верхний уровень документа:

| Поле | Содержимое |
| --- | --- |
| `source_filename` | Имя исходного PDF-файла. |
| `race` | Название, год, даты, место проведения и исходные значения названия и дат. |
| `protocol_metadata` | Погода, главный судья и главный секретарь. |
| `stages` | Этапы с полями `number` и `distance_km`. |
| `participants` | Участники с результатами, общим итогом и штрафами. |
| `warnings` | Общий список предупреждений с указанием участника и этапа, где применимо. |

Каждый элемент `participants` содержит:

- `start_number`, `full_name`, `birth_year`, `region` — данные участника;
- `discipline_code`, `discipline_name` — код и название дисциплины;
- `results_text`, `summary_text` — текст результатов, полученный при разборе;
- `stage_results` — результаты отдельных этапов;
- `summary` — общий результат, статус, время, место из источника и примечание;
- `penalties` — распознанные штрафы;
- `penalty_warnings` — предупреждения о штрафах и примечаниях.

Поля результата этапа:

| Поле | Значение |
| --- | --- |
| `stage_number` | Номер этапа. |
| `raw_result` | Значение из источника, например `02:39:55`, `DNF` или `00:00:00`. |
| `status` | `finished`, `dnf`, `dns`, `dsq` или `null`. |
| `final_time_seconds` | Положительное целое число секунд для `finished`, иначе `null`. |
| `warning` | Предупреждение о неопределённом результате или `null`. |

В `summary` сохраняются `raw_result`, `status`, `total_time_seconds`,
`source_place` и `raw_note`. Место переносится из источника и не пересчитывается.

## Статусы и нулевое время

| Значение в PDF | Обработка |
| --- | --- |
| Положительное время `ЧЧ:ММ:СС` | `finished`, длительность переводится в секунды. |
| `DNF` | `dnf`, время отсутствует. |
| `DNS` | `dns`, время отсутствует. |
| `DSQ` | `dsq`, время отсутствует. |
| `00:00:00` на этапе | Статус и время остаются `null`, добавляется предупреждение. |
| `00:00:00` в общем результате | Ошибка разбора. |

Общий статус переносится из PDF. Скрипт не выводит его из последовательности
этапов и не назначает статус нулевым результатам после `DNF` или `DNS`.

## Штрафы

Поддерживается примечание вида:

```text
штр.вр. 2 мин. п.П.14.11.14
```

Для штрафа сохраняются `seconds`, `rule_reference`, `stage_number` и `raw_note`.
Если этап применения штрафа не указан, `stage_number` остаётся `null`,
а в предупреждения добавляется сообщение об этом.

Нераспознанное примечание сохраняется в `summary.raw_note` и сопровождается
предупреждением. Пустое примечание и значение `0` не создают штраф.

В проверенном протоколе итоговое время этапов уже включает штрафы.
Скрипт сравнивает общий результат с суммой времени этапов и не прибавляет
штрафное время повторно.

## Проверки и ошибки

Перед сохранением проверяются:

- наличие этапов и участников;
- отсутствие повторяющихся номеров этапов и стартовых номеров участников;
- наличие ровно одного результата на каждый этап у каждого участника;
- положительное целое время для результатов со статусом `finished`;
- отсутствие времени у результатов с другим статусом;
- завершение всех этапов у участника с общим статусом `finished`;
- равенство общего времени и суммы времени этапов у финишировавших участников.

При ошибке аргументов выводится сообщение CLI. При ошибке разбора или проверки
скрипт завершается с исключением, JSON не сохраняется. Ошибки чтения и записи
файлов также не скрываются.

Предупреждения не останавливают сохранение: они выводятся в терминал
и остаются в JSON для последующей проверки.

## Ограничения

- Поддерживается PDF с текстовым слоем. Распознавания сканов через OCR нет.
- Excel не поддерживается.
- Строка участника должна извлекаться в одну строку текста.
- Порядок колонок должен соответствовать проверенному шаблону: время и скорость
  каждого этапа, затем средняя скорость, общий результат, место и примечание.
- Этапы в колонках должны идти по возрастанию номеров.
- Поддерживается диапазон дат внутри одного месяца вида `6–15 февраля 2026 г.`.
- Название гонки ожидается в кавычках `«...»`, место проведения — после строки дат.
- Распознаются три дисциплины: `ski_2`, `sled_8` и `sled_8plus`,
  соответствующие названиям в проверенном PDF.
- Фильтр водяного знака использует конкретный оттенок серого из исходного образца.
- Невидимые текстовые значения PDF могут попасть в результат извлечения.
  Неоднозначные данные нужно сверять с исходным протоколом.

Изменение шаблона документа требует проверки правил разбора.

## Результат на проверенном протоколе

Для файла `Total_result_Avacha-2026.pdf`:

| Показатель | Значение |
| --- | --- |
| Гонка | Берингия. Авача 2026 |
| Этапы | 6 |
| Участники | 21 |
| Результаты этапов | 126 |
| Штрафы | 3 |
| Предупреждения | 11 |

Из 11 предупреждений 8 относятся к нулевому времени этапов,
а 3 — к штрафам без указания этапа применения.
